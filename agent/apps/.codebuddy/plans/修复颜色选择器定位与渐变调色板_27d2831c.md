## 用户需求

修复 jvenn.html 在移除 Bootstrap CSS 后颜色选择器（bootstrap-colorpicker）出现的两个问题：

1. 点击颜色触发器（`.colorpicker-component` 的 div）后，选择器弹层未出现在触发按钮/鼠标旁，而是定位到页面左下角。
2. 选择器弹层内的饱和度/色相调色板显示为纯色，没有原本的梯度渐变效果。

## 核心诉求

- 颜色选择器点击后应相对触发元素就近弹出（按钮旁），不再跑到左下角。
- 调色板恢复有梯度的彩色显示（饱和度方块渐变 + 色相长条渐变）。
- 不得重新引入 Bootstrap CSS，保留 bootstrap-colorpicker 的 css/js 依赖。
- 明暗主题切换与整体新样式风格保持不变。

## 功能描述

- 恢复 colorpicker 弹层的定位上下文，使其相对触发元素正常定位。
- 用 CSS 渐变（不依赖缺失的 PNG 图片）重建饱和度与色相梯度，恢复彩色调色板。

## 技术栈

- 纯静态 HTML + 内联 `<style>`（jvenn.html），沿用 kb.css 设计令牌体系。
- 第三方组件：bootstrap-colorpicker（保留其 css/js），jQuery + bootstrap.min.js（tab 插件）。
- 不引入任何新框架，仅在既有 jvenn.html 样式块内修复。

## 问题根因（已探查确认）

1. **定位错误**：`.colorpicker` 弹层默认 `position:absolute; top:0; left:0`，依赖触发容器（`.input-append.colorpicker-component`）提供 `position:relative` 定位上下文。当前 `.jvenn-app .input-append` 被写为 `display:inline-flex`（jvenn.html 第 332-336 行），且未声明 `position:relative`，导致弹层相对最近定位祖先/body 定位到页面左下角。
2. **纯色调色板**：`vendor/css/bootstrap-colorpicker.min.css` 通过 `background-image: url("../img/bootstrap-colorpicker/saturation.png")` 等加载渐变图；但 `vendor/img/bootstrap-colorpicker/` 目录及 4 张 PNG（saturation/hue/alpha/hue-horizontal）在整个 apps 目录均不存在（已搜索确认），图片加载失败，弹层显示纯色。

- 注：图片为二进制资源，无法在仅文本修改中重建；正确做法是用 CSS 渐变覆盖其 `background-image`，无需二进制文件。

## 实现方案

### 策略

采用"定位上下文恢复 + CSS 渐变覆盖"两段式修复，全部在 jvenn.html 的内联 `<style>` 中完成，不触碰 bootstrap-colorpicker.min.css 原文件（保持其 intact 以便复用）。

### 关键决策

1. **恢复定位**：为 `.jvenn-app .input-append.colorpicker-component`（即触发器）补回 `position:relative`，并保留其作为 colorpicker 触发容器的语义；`.add-on` 仅作为视觉触发按钮，不影响弹层定位。这样弹层 `top:0;left:0` 会贴着触发器左上角（Bootstrap 原版行为），视觉上即"按钮旁"。

- 权衡：不改用 `inline-flex` 容器包裹弹层（弹层由 JS 插入到触发器内部，绝对定位即可）。保持 `.input-append` 为 `inline-block`/`inline-flex` + `position:relative` 兼容两者。

2. **渐变重建**：在 jvenn.html `<style>` 末尾追加覆盖规则，用 CSS 渐变模拟原 PNG：

- `.colorpicker-saturation`：用 `radial-gradient(circle at center, #fff 0%, rgba(255,255,255,0) 60%), linear-gradient(to top, #000, transparent), linear-gradient(to right, hsl(0,100%,50%), hsl(60,100%,50%), hsl(120,100%,50%), hsl(180,100%,50%), hsl(240,100%,50%), hsl(300,100%,50%), hsl(360,100%,50%))` 三层叠加模拟饱和+明度+色相。
- `.colorpicker-hue`：用 `linear-gradient(to bottom, #f00 0%, #ff0 17%, #0f0 33%, #0ff 50%, #00f 67%, #f0f 83%, #f00 100%)` 模拟色相条（与原 hue.png 一致方向，垂直）。
- 这些覆盖规则需放在 bootstrap-colorpicker.min.css 之后加载（内联 style 在 head 中位于 link 之后，满足），特异性 `.jvenn-app .colorpicker-saturation` 高于 `.colorpicker-saturation`，确保覆盖生效。
- 权衡：CSS 渐变与原始 PNG 视觉接近，无需二进制资源，零额外网络请求，性能无损。

### 性能与可靠性

- 纯 CSS 覆盖，无 JS 改动、无额外请求；`app.js` 的 `.colorpicker()` 初始化与 `changeColor` 回调不受影响。
- 渐变声明为静态样式，渲染一次，无重排开销。

## 实现注意事项

- 仅修改 jvenn.html 的内联 `<style>`，不改动 bootstrap-colorpicker.min.css、app.js、jvenn.min.js。
- 保留 `display:none` 的隐藏 input（`.form-control`）及 `.add-on > i` 色块（由 app.js 写 background-color）。
- 覆盖规则的 CSS 选择器需带 `.jvenn-app` 前缀或足够特异性以战胜 bootstrap-colorpicker.min.css 的同级选择器。
- 改动后需在浏览器打开 jvenn.html，点击任一组颜色触发块验证：弹层出现在按钮右侧/下方、调色板显示彩色梯度；并确认明暗主题切换仍正常。

## 关键代码位置

- 修改点1（定位）：jvenn.html `第332-336行`

```css
.jvenn-app .input-append {
  display: inline-flex;
  align-items: center;
  vertical-align: middle;
}
```

改为补充 `position: relative;`（使 colorpicker 弹层相对此触发器定位）。

- 修改点2（渐变覆盖）：在 `</style>` 前追加

```css
.jvenn-app .colorpicker-saturation {
  background-image:
    radial-gradient(circle at center, #fff 0%, rgba(255,255,255,0) 60%),
    linear-gradient(to top, #000, transparent),
    linear-gradient(to right, hsl(0,100%,50%), hsl(60,100%,50%), hsl(120,100%,50%), hsl(180,100%,50%), hsl(240,100%,50%), hsl(300,100%,50%), hsl(360,100%,50%));
}
.jvenn-app .colorpicker-hue {
  background-image: linear-gradient(to bottom, #f00 0%, #ff0 17%, #0f0 33%, #0ff 50%, #00f 67%, #f0f 83%, #f00 100%);
}
```

本任务为已有页面的局部样式缺陷修复（颜色选择器定位与调色板渐变），不涉及整体 UI 重构或新页面创建，因此不输出完整设计系统，仅确保修复后的颜色选择器与现有基于 kb.css 令牌的暗/亮主题风格协调一致。修复后的弹层沿用 token 边框/圆角观感，无明显视觉割裂。
